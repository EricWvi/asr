### ASR 实测（2026-10-24，北京）

- 地址是 `wss://<host>/api-ws/v1/inference`，host 已经包含业务空间和地域，所以配置里只需要 host。
- 延迟：连接加 `task-started` 约 0.2–0.26 秒；开始说话约 0.5 秒后出第一批字，之后大约每 0.4 秒更新一次；音频结束后 0.04–0.4 秒拿到定稿和 `task-finished`。
- 中间结果每次都是整句全文，按 `sentence_id` 替换，不能累加。最早几条可能是空字符串。
- 服务端自带 VAD：停顿约 1.5 秒就会断句，同一次任务里会有多个 `sentence_id`。前端一次按住说话可能拿到多句定稿，要按顺序拼接。
- 定稿可能和中间结果不一样，甚至为空：0.3 秒的短音频，中间结果是「嗯，」，定稿是空字符串。一律以 `sentence_end=true` 的文本为准，空的就丢弃。
- 只有静音时，会收到一条空定稿，然后正常 `task-finished`，不报错。
- 74 秒连续推流正常，没有遇到时长上限。更长的时长没有测，实现时设一个上限（例如 5 分钟）。
- 数字会被规整成阿拉伯数字（「三点」→「3点」），标点会自动加。
- `disfluency_removal_enabled: true` 会去掉「嗯」这类口头语，打开。口语到书面语的梳理交给「整理」。`language_hints: ["zh"]` 对普通话结果没有可见差别，保留。
- `task-finished` 的 `usage.duration` 是计费秒数，可以记到日志里。

### 整理实测（2026-10-24）

「整理」的含义：把口语稿梳理成规范的书面 Markdown，保留全部信息，不总结。提示词原型在 .tmp/asr-probe/tidy.py。

- 可用模型：`deepseek-flash`（V4.1-Flash）和 `deepseek-v4-pro`，接口是 OpenAI 兼容的 `https://api.deepseek.com/chat/completions`。
- 一段约 300 字、带改口和待办的口语稿：
  - `deepseek-flash`（默认思考）：首字 2.2 秒，总计 2.9 秒。结构合理，改口取后者，待办识别成 `- [ ]`，信息没有遗漏。
  - `deepseek-v4-pro`：总计 14 秒，效果和 flash 差不多，不划算。
  - `deepseek-flash` 关闭思考（`thinking: {type: disabled}`）：1.3–1.7 秒，但会过度分节，还会调换原文顺序。不采用。
  - `reasoning_effort: "low"` 没有明显提速。
- 一句话的短稿只修语句，不硬加结构，耗时约 1 秒。
- 结论：默认用 `deepseek-flash`，开启思考，流式返回。思考阶段约 2 秒，前端要显示「整理中」。
- 实现时要把待整理段落之前的标题结构作为只读上下文传进去，让新加的标题层级和文稿已有的衔接。

实现时定下的细节（效果见 design/pc.html 的 `#rec`、`#countdown`、`#asr-error`、`#mic-denied`、`#no-mic`）：

- 空格：按下立即打开麦克风并缓存音频；300 ms 内松开算短按，取消录音并打一个空格（只在正文有焦点时）；超过 300 ms 才开始识别，缓存的音频一起发出，开头不丢字。标题、侧栏重命名、菜单里的空格照常输入。鼠标按住按钮遵守同样的 300 ms，短按什么也不做。
- 插入点是按下时的选区，随编辑映射位置。说话时所有文字（含已定稿的句子）都只淡色显示在插入点，不写进正文；松手拿到全部定稿后一次写入，一次撤销全部撤掉，光标停在插入文字之后。多句直接拼接，不加空格或换行。
- 失败（断网、超时、上游报错）时保留已定稿的句子，丢掉没定稿的半句，提示「识别中断，最后一句没有识别完」；没有半句时提示具体原因。定稿为空时什么也不插入。
- 单次最长 5 分钟：最后 30 秒在按钮上显示剩余时间，到时自动按松手处理，提示「已到 5 分钟上限，自动结束」。
- 切换文稿或切回键盘模式时，正在进行的录音直接丢弃。窗口失焦或页面隐藏按松手处理。
- 换行按钮的效果和回车相同，列表里会续写下一项。整理按钮在阶段 5 之前保持禁用。
- 前后端协议：浏览器发二进制 PCM 帧，松手后发 `{"type":"finish"}`；服务端回 `partial`/`final`（带 `sentence` 和 `text`），最后 `done` 或 `error`（带中文 `message`）后关闭。连接建立前的音频由浏览器缓存。服务端在上游 task-started 后才读音频；10 秒收不到音频、finish 后 10 秒没有 task-finished、音频超过 5 分 10 秒，都按失败处理。握手由 websocket 库校验 Origin，防跨站。
- 麦克风只在按住期间打开，浏览器的录音指示只在说话时出现；AudioContext 和 worklet 复用。
- 没配置 `dashscope.host` 或 API Key 时服务照常启动，语音识别提示「语音识别未配置」。

## 阶段 5：整理

- [x] 记录转写区间：每次定稿后标记一个区间，随编辑映射位置；用户手动改过的区间就移除标记。区间和文稿一起持久化，刷新页面后还在。
- [x] 后端 `/api/tidy`：调用 `tidy.base_url` 的 OpenAI 兼容接口，流式返回结果。代码只发标准字段（`model`、`messages`、`stream`）；厂商专有参数（如 DeepSeek 的 `thinking`）放在配置 `tidy.extra_body`，原样合并进请求体，与标准字段冲突时以代码为准。当前 `deepseek-flash` 默认开启思考，`extra_body` 可以不填。提示词从 .tmp/asr-probe/tidy.py 移进代码，附带文稿已有的标题结构作为上下文。
- [x] 点「整理」后，把上次整理之后的待整理区间发出去，结果原地替换，之后清空标记。整理是一次可以撤销的事务。
- [x] 没有待整理内容时，按钮禁用，悬停时说明原因。

实现时定下的细节（效果见 design/pc.html 的 `#tidy-peek`、`#tidying`、`#tidied`、`#tidy-empty`、`#tidy-error`，落选变体 `#tidy-peek-fill`、`#tidying-pulse`）：

- 区间存在 documents 表的 `tidy_ranges` 列（JSON，`[[from, to], …]`，按 UTF-16 计的偏移，和 CodeMirror 一致），随正文在同一次保存里提交，沿用最后写入为准。服务端只校验有序、不重叠、不越界。
- 手动编辑碰到区间内部就去掉这个区间的标记；紧贴区间边界输入不算。撤销会把编辑或整理去掉的标记恢复，重做再去掉。在待整理文字中间再说一句，算进原来的区间。
- 分段：相邻、或中间只隔空白和换行的区间合成一段；被手写文字隔开的各自成段，每段一个请求并发发出，全部回来后在同一个事务里各自原地替换（一次撤销）。手写文字一个字不动。
- 每段附带只读上下文：段落之前的所有标题行（跳过代码块），以及段落起止行上前后已有的文字（如列表符号 `- `）。有行首或行尾文字时要求模型只输出一段不换行的文字，前端也会把换行去掉。
- 整理中：待整理文字上扫过一道文稿 deep 色的微光，按钮显示转圈和「整理中」，两侧按钮同宽，说话按钮不跳动。整理中不能说话（按钮变淡，空格照常打空格），正文可以编辑；某段在整理期间被手动改过，这段的结果丢弃，提示「整理期间文字被改动，改动的部分没有替换」。再点按钮或按 Esc 取消，什么都不替换；切换文稿或切回键盘模式也会取消。
- 悬停「整理」按钮时，待整理文字显示 deep 色点状下划线；平时不显示。整理后的文字带转写同款下划线，2.5 秒后淡出。
- 失败（接口报错、超时、流中断、模型因长度截断、输出为空）都不替换，标记保留，toast 显示原因；多段里部分失败时，成功的段照常替换。没配置 `tidy` 时提示「整理未配置」。单段最多 20000 字，单次最长 2 分钟。
- `/api/tidy` 协议：请求 `{"text","headings","prefix","suffix"}`；响应是逐行 JSON，`{"type":"delta","text"}` 若干条，最后 `done` 或 `error`（带中文 `message`）。前端等到 `done` 才替换，没收到 `done` 按失败处理。

- [x] 侧栏搜索入口，结果高亮命中词。

实现时定下的细节（效果见 design/pc.html 的 `#search`、`#search-empty`、`#search-hit`，落选变体 `#search-hit-mark`；原型右下角的「状态」菜单列出全部锚点）：

- 索引是 `documents_fts`（FTS5，trigram 分词，外部内容表指向 documents），由触发器随标题和正文同步；只改颜色或待整理区间不重建索引。回收站里的文稿仍在索引里，查询时排除。
- 查询按空格分词，每个词都要出现，不分大小写，最多 8 个词。3 个字及以上的词走索引；1–2 个字的词（trigram 查不到）退回 LIKE 扫描，`%`、`_` 按字面匹配。
- 排序：标题含任一词的在前，其余按最后修改时间，最多 50 条。片段取正文里第一处命中所在的行，去掉 Markdown 标记，命中前留 10 个字；只有标题命中时用平常的摘要。
- 正文按 Markdown 原文索引，链接和图片地址里的字也能搜到。
- 界面：侧栏「新建文稿」下面是搜索框，⌘K（其他系统 Ctrl+K）聚焦，Esc 清空并回到正文。按回车才搜索（输入法上屏的回车不算），文稿列表就地换成结果（「找到 N 篇」）；删光文字、点 × 或 Esc 立即回到列表。命中词用该文稿的 mark 色；没有结果时显示「没有找到「…」」。颜色筛选对结果同样生效，右键菜单照常可用。
- 打开结果：正文里所有命中用文稿 deep 色 35% 的淡底标出，光标放在第一处并滚到视野中间；一编辑或清空搜索就清除。光标所在行按实时预览规则显示源码。
- 接口：`GET /api/search?q=`，返回和文稿列表相同的条目，`snippet` 是命中片段；查询超过 200 字返回 400。

## 阶段 8：设备 token 与推送通道

- [x] devices 表：设备名、平台、token 哈希、最近使用时间。
- [x] 原生客户端登录：客户端打开系统浏览器访问 `/auth/device/login`，走同一套 OIDC，回调后通过自定义 scheme（安卓）或 loopback（Mac）把 token 交回客户端。需要防 CSRF，code 只能用一次。
- [x] API 同时接受 Cookie session 和 `Authorization: Bearer <设备 token>`。
- [x] 网页端设备管理：查看设备并吊销。
- [x] 用户级 WebSocket 推送：Mac 客户端常驻连接，并上报最近一次键盘鼠标活动时间。
- [x] 「发送到电脑」默认推给最近活跃的那台 Mac，安卓端可以手动切换目标。没有 Mac 在线时直接返回失败，不排队。
- [x] 发送的是识别原文，不整理，服务端不留存。

实现时定下的细节（效果见 design/pc.html 的 `#user-menu`、`#devices`、`#devices-revoke`、`#devices-empty`，以及 design/device-auth.html）：

- 登录流程参照 RFC 8252：客户端带上 `platform`（`mac` 或 `android`）、`name`、`redirect_uri`、`state`、`code_challenge`（只接受 `code_challenge_method=S256`）打开 `/auth/device/login`。这些参数跟着登录 Cookie 走一遍 OIDC，回调仍是 `/auth/callback`，Authelia 不用另外登记。回调后跳到 `/auth/device/confirm` 授权确认页，显示设备和当前账号；点「允许」才发 code，点「取消」带 `error=access_denied` 回到客户端。两种结果都带回客户端的 `state`。浏览器本身不会因此登录网页。
- `redirect_uri` 白名单：Mac 只能是 `http://127.0.0.1:<任意端口>/callback`，安卓只能是 `tingxie://auth/callback`。
- 确认页由 Go 直接渲染（internal/auth/device.go），不依赖前端应用，跟随系统亮暗色。待确认的请求放在内存里，10 分钟有效，用 `asr_device` Cookie（`/auth/device/`，Lax）对上，提交时检查同源，并核对表单里的 id 和 Cookie 是否一致。允许后，页面用脚本跳回客户端，同时留一个「点这里」链接，以防浏览器拦截不是用户手势触发的跳转。
- code 放在内存里，60 秒有效，只能用一次（换失败也作废）。客户端 `POST /auth/device/token {"code","code_verifier"}`，拿到 `{"token","device"}`。token 是 `asr_d_` 加 32 字节随机数，库里只存 SHA-256，不过期。每次登录都新建一个设备；客户端退出登录时 `DELETE /api/devices/<自己的 id>`。
- Bearer 请求不做同源检查；`dev_user` 模式下也认 Bearer，没有 Bearer 的请求才按 dev 用户处理。`dev_user` 模式的设备登录跳过 OIDC，直接到确认页。设备的最近使用时间最多 5 分钟写一次。
- 设备可以列出设备，只能吊销自己；吊销别的设备只能在网页上（Cookie 会话）操作。吊销后，那台设备的推送连接立刻断开（关闭码 1008，原因 `device revoked`）。
- 设备管理：用户菜单里依次是「个人资料」「设备」「退出登录」。对话框列出平台图标、设备名，以及「在线」（Mac 有推送连接时显示，薄荷色加深的圆点）或「x 分钟前使用」、平台、登录日期；在线的排在前面，其余按最近使用时间排。悬停才出现「吊销」，点一次变成红色的「确认吊销」，3 秒内再点才吊销。对话框打开时每 10 秒刷新一次。
- 推送：`GET /api/devices/stream`（WebSocket），只接受 Mac 的设备 token。服务端每 20 秒 ping 一次，10 秒内没有 pong 就断开；同一台设备的新连接会顶掉旧连接。Mac 有键盘鼠标操作时发 `{"type":"activity"}`，最多每 5 秒一次，时间以服务端收到为准。连接和活动时间只放在内存里。
- `POST /api/send {"text","device_id"?}`：不指定 `device_id` 时，选在线 Mac 里最近有活动的一台（都没有活动时，选最后连上的）。服务端推 `{"type":"insert","id","text"}`，等 Mac 回 `{"type":"ack","id","error"?}`，最多 5 秒。成功时返回 `{"device":{"id","name"}}`；没有在线的 Mac 返回 409「没有在线的电脑」，指定的 Mac 不在线返回 409「这台电脑不在线」，超时返回 504「电脑没有响应」，Mac 报错时返回 502 和它给的原因，连接中途断开返回 502。文字最多 20000 字，不写库，也不记日志。网页的 Cookie 会话也能调用，但网页界面不提供这个功能。
- `GET /api/devices` 返回每台设备的 `online` 和 `last_active_at`（毫秒），安卓用它显示和切换目标。
- 没有原生客户端时的测试：Go 测试用 coder/websocket 模拟 Mac（internal/server/devices_test.go）；Authelia 契约测试走一遍完整的设备登录。手动演示用 .tmp/devtool（不进仓库）。
- 留给阶段 9、10：安卓上用 Custom Tab 打开登录页时，要真机确认脚本跳回 `tingxie://` 能触发；Mac 的 loopback 回调页面由客户端自己返回。

## 个人资料与头像

- [x] 用户菜单进入「个人资料」对话框，可以更换和移除头像。

实现时定下的细节（效果见 design/pc.html 的 `#profile`、`#profile-avatar`、`#avatar-crop`、`#avatar-saving`、`#avatar-error`）：

- 对话框宽 360px：88px 的头像（悬停出现相机图标，点击即选图）、显示名、邮箱，下面是「更换头像」，有头像时多一个「移除头像」。选到不支持的格式时，在按钮下面用红字提示。
- 选图后对话框切成「裁剪头像」：320×280 的深色舞台，直径 240px 的圆形取景框，框外压暗。拖动挪位置，滑块或滚轮缩放（1–4 倍，滚轮以指针为中心）；图片始终盖满圆圈。「保存」在浏览器里裁成 256×256，按 WebP 0.9 上传（浏览器不支持 WebP 编码时得到 PNG），保存中按钮显示转圈，失败时在按钮左边显示原因。主按钮是墨色底。
- 接口：`PUT /api/me/avatar`（请求体是图片字节，不超过 1 MB，格式按内容嗅探，只收 PNG、JPEG、GIF、WebP）返回 `{"avatar_url"}`；`DELETE /api/me/avatar`；`GET /api/me` 多返回 `avatar_url`（没有头像时为空字符串）。
- 存储：users 表的 `avatar` 列存头像 ID（16 位随机串），文件在 `<data_dir>/avatars/<用户 id>/<ID>`。每次上传换新 ID、删旧文件，所以 `GET /api/avatars/<ID>` 可以永久缓存；不是当前 ID 的请求返回 404。头像和文稿图片分开存，不会被未引用图片的清理删掉。
- `/api/me` 每次从库里读用户，`dev_user` 模式缓存的用户不会让新头像失效。设备授权确认页把头像以 data URI 内嵌，因为那个浏览器不一定有网页会话；确认页的品牌区也换成了新 logo 和「听·写」。

实现时定下的细节（工程在 `android/`，包名 `top.onlyquant.tingxie`，minSdk 29，自己安装 APK）：

- 构建：AGP 9 + Kotlin 2.4 + Compose BOM，用 Android Studio 自带的 JBR（`JAVA_HOME=/Applications/Android Studio.app/Contents/jbr/Contents/Home`），`cd android && ./gradlew installDebug`。debug 包允许明文 HTTP，方便连局域网的开发服务；release 先用 debug 签名。
- 颜色 token 由浏览器解析原型的 oklch 混色得到，写死在 `ui/theme/Theme.kt`；图标由原型的 SVG 生成（`ui/Icons.kt`）。
- 登录：服务器地址保存在本地，登录页可改（局域网开发服务填 `http://<Mac IP>:36750`）。PKCE 的 state 和 verifier 存盘，浏览器往返期间进程被杀也能接上。从 Custom Tab 回来却没有回调，按「已取消登录」处理。设备名取系统的设备名称，没有就用型号。token 失效（401）时回到登录页，提示「登录已失效，请重新登录」；退出登录要连得上服务器，离线时提示「离线时无法退出登录」。
- 文稿：列表和打开过的文稿缓存在本地，离线可以看。保存照搬网页端的保存队列：防抖 800 ms、失败 5 秒后重试；颜色立即保存；没发出的修改存盘，下次启动接着发。保存状态的文案和网页一致（已保存、保存中、保存失败、离线）；网页去掉了字数，安卓也不显示。新建后一个字没写就返回列表，这篇自动删除。
- 查看模式：段落间距沿用原型 CSS 的外边距，行内换行按换行显示（和网页编辑器一致）。只有 `[文字](url)` 是链接，引用式链接和脚注按原文显示。行内代码、高亮、搜索命中的底色贴着字形画圆角，不撑满行高。表格按列对齐（`:---:`、`---:`）。 粗体、斜体、删除线、高亮的闭合规则和网页编辑器一样对中文友好（`ui/CjkFlavour.kt`）：全角标点后紧跟中文也能闭合，如 `**加粗。**有`。
- 录音：按住先开麦克风缓存音频，300 ms 后才识别；手指上移超过 64dp 进入取消状态；5 分钟上限、最后 30 秒倒计时、离开文稿时丢弃、应用切到后台按松手处理，规则同网页。查看模式写到文末，编辑模式写在光标处。写入后转写区间记为待整理（规则移植自 `editor/tidy.ts`），手动改到区间内部就去掉标记。debug 包若有 `files/fake-mic.wav`，就用它代替麦克风，方便在模拟器上测试。
- 编辑模式：点正文时，光标放在所点那一段的对应位置，这一段在屏幕上的位置不变。编辑器保留原文的空行（每行一个行高，同原型），代码块整块画底色。回车续写列表，空的列表项上回车结束列表。系统返回键、「完成」和工具栏的收起键盘都会回到查看模式。 光标在列表项文字开头回车，文字移到下一个新项，上面留一个空项（保留标记后的空格），同网页。
- 回到应用（onResume）时重新读列表和打开的文稿；文稿的正文、待整理区间、标题或颜色在别的设备上改过，就原地换成新版本，光标尽量留在原处。本机有没保存完的修改或正在录音时跳过，同网页 `lib/remote-edits.ts`，整理进行中也跳过。
- 整理：分段、上下文、清理结果、整理期间改过的段不替换、失败提示都照网页（`data/Tidy.kt`）。点「整理」开始，按钮变成转圈加「整理中」，说话按钮变淡；待整理文字变淡，一道文稿 deep 色的微光每 1.6 秒扫过（`ui/Shimmer.kt`，查看和编辑模式都有）。再点取消，离开文稿也取消。替换后新文字带转写同款下划线，底部提示条「已整理 · 撤销」（部分失败或被改动时换成对应提示，仍带撤销），撤销换回原文和待整理区间；之后正文再有任何改动，提示条立即收起，不能再撤销。原型 `#tidied` 已加上这个提示条。
- 个人资料（`ui/ProfileScreen.kt`）：点头像、相机标记或「更换头像」打开系统照片选择器（`PickVisualMedia`，不要存储权限）。`ImageDecoder` 解码（含 HEIC，按 EXIF 摆正，长边超过 2048 先缩小），全屏黑底裁剪，取景框直径 320dp（屏幕放不下时缩小），框外压暗 62%，拖动、双指缩放 1–4 倍，图片始终盖满取景框（`data/Crop.kt`）。裁剪页状态栏图标改成白色。「保存」裁成 256×256，按 WebP 90 上传，成功回到个人资料页；失败在按钮左边显示「保存失败，请重试」。解码失败提示「无法打开这张图片」。「移除头像」直接移除，不二次确认（同网页）。离线时点这些按钮提示「离线，只能查看」。
- 设备页（`ui/DevicesScreen.kt`）：只读。本机排第一并标「本机」，其余在线的在前、再按最近使用排；每行是平台图标、设备名、「在线」（薄荷 deep 色圆点）或「x 分钟前使用」、平台、登录日期，和网页一致。停在这页时每 10 秒刷新一次，Mac 断开后会变成不在线。本机的「x 分钟前使用」取服务端记录的时间，不一定是「刚刚」。
- 发布与更新（`data/Update.kt`、`.github/workflows/release.yml`，原型「更新」分组）：推 `v*` 标签后，CI 构建签名 APK，校验证书指纹，把 APK 和 `latest.json` 附到 GitHub Release，不经过草稿。版本号取自标签，`1.2.3` 对应 versionCode 1002003。app 读 `releases/latest/download/latest.json`，预发布版本不算最新。启动或回到前台时最多每天查一次，失败不提示；同一版本的提示条只出现一次，之后在个人资料页底部的卡片更新。下载中可以离开页面，其他页面显示进度提示条，个人资料页只看卡片。下载后校验 sha256，自动拉起系统安装器；退出安装后显示「已下载 · 安装」，不用重新下载。不强制更新。没有网络代理时手机可能连不上 GitHub，只能提示失败。
- 查看和编辑的切换（`ui/DocScreen.kt`，真机上定下）：切换期间关掉系统的自动滚动，只由代码滚动一次。进入编辑时点中的段落不动；光标那行会被键盘挡住时，按键盘的最终高度上移，留 24dp。退出编辑时，光标所在段（光标不在屏幕内时取屏幕顶部那段）留在原来的屏幕位置，等 Markdown 解析完再放回，期间保持内容高度。切换瞬间正文隐藏，只有一两帧。两种模式正文底部都留 200dp。内容变化时保留旧的渲染结果直到解析完成（`retainState`），勾选待办等操作不会丢滚动位置。编辑工具栏两侧等宽（92dp），说话按钮居中（原型已同步）。
- 发送到电脑（`ui/SendScreen.kt`、`data/Sends.kt`）：记录存在 `files/sends.json`，只保留 30 天内的（读入、发送和打开页面时清掉过期的，不限条数），退出登录时删除；发送不依赖页面，离开页面不影响正在发的。选中的电脑存在本地，重启后还在；它退出登录后回到「自动」。「自动」卡片上的电脑按在线 Mac 的最近操作时间推断，实际发到哪台以服务端返回为准。停在这页时每 10 秒刷新在线状态，发送失败后立刻刷新。重发成功的记录时新增一条；重发失败的记录时，原记录换成新的那条，不留两份。发送途中进程被杀，下次打开显示「发送中断，文字已保留」。识别中的文字不截断，已发送的最多显示 4 行。识别失败时已定稿的句子照常发送并提示错误，同文稿。没有网络时顶部提示「离线，只能查看」（原型 `#send-net-off`），隐藏说话按钮，复制可用，重发提示离线。读不到电脑列表时卡片显示「读不到电脑列表」和原因。卡片底部一行在所有状态下都是按钮的高度，从识别到发送完成卡片不跳动（原型已同步）。

原型定下的设计（效果见 design/android.html，右下角「状态」菜单列出全部锚点；落选变体 `#doc-fab`、`#asr-error-card`、`#list-blur`、`#list-fab-wide`）：

实现时定下的细节（工程在 `mac/`，Swift Package，macOS 13+，bundle ID `top.onlyquant.tingxie.mac`）：

- 构建：`task build:mac` 打出 `mac/build/TingXie.app`（`VERSION=1.2.3` 设版本，`UNIVERSAL=1` 打通用二进制），`task run:mac` 打包并打开，`task test:mac` 跑 `TingXieCore` 的单元测试（已并入 `task test`）。不依赖 AppKit 的逻辑（协议、截止时间、PKCE、回调解析、服务器地址规整、版本比较、菜单文案）放在 `TingXieCore`。菜单栏图标和应用图标由 `mac/scripts/icons.py` 从原型的 logo 生成。
- 开发时用 `defaults write top.onlyquant.tingxie.mac server http://127.0.0.1:36750` 指向本地服务；第一次运行会打开「开机时启动」，开发机上先 `defaults write top.onlyquant.tingxie.mac launchAtLoginInitialized -bool true` 跳过。开发版和正式版是同一个 bundle ID 和证书，共用辅助功能授权、钥匙串里的登录信息和设置，不要同时运行。
- 登录：PKCE 加 127.0.0.1 随机端口（Network 框架），10 分钟超时，可以从菜单取消。设备名取「电脑名称」，最长 64 字。回调页由客户端返回，样式同确认页。
- 连接：日志在系统日志里，`log show --info --predicate 'subsystem == "top.onlyquant.tingxie.mac"'`。连接失败按 1、2、4…30 秒退避，连上后断开 1 秒后重连；唤醒或网络恢复时立刻重连（正在建立的连接不打断）。客户端每 25 秒 ping 一次，10 秒没回就断开重连；20 秒连不上也重来。401、403 或关闭原因 `device revoked` 时退出登录，提示「登录已失效，请重新登录」。最近操作按系统的空闲时间判断（不用权限），空闲不到 5 秒就每 5 秒报一次 activity。
- 菜单：最近插入的时间贴着菜单右边缘，菜单建好后把右对齐制表位往右推到菜单刚好不变宽为止。「退出听·写」不显示 ⌘Q，因为有快捷键的话每一项右边都会留出一列，时间贴不到边。没有邮箱时账号行只显示名字。
- 开发：`open --env TINGXIE_DEMO=1 mac/build/TingXie.app` 启动时填入示例记录并打开菜单，方便截图。要用 `open` 启动，直接在终端里跑可执行文件，辅助功能权限会算到终端（如 VS Code）头上。
- 坑：`URLSessionWebSocketTask` 在连上之前被取消，`receive()` 永远不返回；所以等待也由委托的 `didCompleteWithError` 结束。
- 插入：剪贴板写入时带 `org.nspasteboard.TransientType`，剪贴板管理器不会记录；0.8 秒后如果剪贴板没被别人改过，就恢复原内容（连续插入时只恢复第一次之前的）。没有辅助功能权限时只复制到剪贴板，回「电脑没有开启辅助功能权限，文字已复制到剪贴板」；登录后会弹一次系统的授权提示，之后每 2 秒检查一次权限，开了之后橙点自己消失。截止时间在主线程真正处理时才判断，主线程卡住也算。

原型定下的设计（效果见 design/mac.html，右下角「状态」菜单列出全部锚点；整体风格选了系统菜单，落选的「系统菜单 + 头部」「弹出面板」已删除）：

- 原生 NSMenu。菜单栏图标是 logo 的单色剪影（template image，写字的横线挖空）：正常、变淡（未登录或没连上）、右上角橙点（缺少辅助功能权限）。
